# Shared customer selections and supplier pricing requests

The portal now has a Worker backend and a D1 customer_workspace table. Fixtures/finishes preferences, mood boards, SH project facts/base specifications, checked measurements, supplier records and pricing-request snapshots are stored under the authenticated Sites account ID. Reopening the private portal on another device with that same account loads shared data. Existing records from the first browser are imported when the shared workspace is empty. Other prototype collections and uploaded files remain device-local.

The private audience is unchanged. Business-role switching remains a preview; this release does not establish separate customer/supplier identities or project memberships. Before opening the portal to multiple business accounts, implement verified membership and permissions for each project. API requests require Sites identity; writes require same Origin and a known revision. Conflicting device saves are rejected. Refresh loads the shared version and retains prior local values as a browser backup. The UI shows loading, pending, saved and failed states; a local save alone is not presented as a shared-save confirmation.

Supplier pricing workflow: SH registers suppliers and pricing email addresses. SH can enter checked measurement rows with category, quantity, m²/lm/ea unit, drawing/schedule source and revision. Customer quantities may use these rows, an exact project inventory line or reviewed manual input. No automatic PDF take-off or floor-area substitution is performed. Measurement rows form the current input boundary for the SH kitset pricing system; automatic external pricing-system integration remains pending its schema/API.

A draft request snapshots the SH-registered supplier, specification, finish, reviewed quantity/unit and source. The customer reviews the snapshot and marks it Ready for supplier. No private contractor costs are included. Text export and Google Workspace/Gmail compose are available; compose does not send mail or confirm delivery. Direct hosted Gmail sending remains unconnected: the required Sites plugin-eligibility discovery tool is unavailable in this session, so no connector IDs, write grants or provider credentials were guessed. Future direct sending needs verified Sites eligibility, visitor consent and a server-owned send action with duplicate prevention and delivery status.

Build: node scripts/build-shared-worker.cjs embeds the existing static files into a dependency-free ESM Worker under ignored .site-build/dist. The archive contains server/index.js and .openai/hosting.json plus schema-only SQL/journal under .openai/drizzle. The existing dist files remain the maintained UI source. Tests: node scripts/check-workspaces.cjs and node scripts/check-customer-api.mjs; SQLite migration/revision queries also checked locally. Hosted storage must additionally be verified after deployment.
