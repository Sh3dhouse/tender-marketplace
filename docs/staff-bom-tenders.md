# SHP 1.3 BOM and tender readiness

Module SHBOMTender exposes pages, render and bind, with validateCSV for meaningful import validation tests. Context is the existing staff context, including local IndexedDB files.put/get helpers. Load staff-bom-tenders.js and staff-bom-tenders.css. Project selector persists staffProjectId. Root can call seedTestProjects(ctx,{model:'Gable 120',region:'Waikato'}) after workspace initialization and save the resulting store; it returns the number of newly created projects and notifies only for new records.

Actual BOM PDFs are uploaded by the user into local IndexedDB, capped at 10 MB and checked for a PDF header. Metadata lives in bomDocuments and documents. No provided source PDF, source text, customer name, site address, source quantities or price is seeded in committed assets. Files are device-local; metadata does not make a document downloadable on another device. BOM status is SH’s recorded review status, not external approval. Documents include attachment metadata and ownerId so other modules can retrieve files after checking project/owner. No automatic PDF extraction is claimed.

Inventory CSV columns are exactly category,item_code,description,specification,quantity,unit. Quoted fields, commas and multiline text are supported. Preview is held in memory and must be reconciled before import. Positive quantities and explicit accepted units are required; import is capped at 5,000 rows. Each row retains sourceLine, sourceBOMId, sourceBOMVersion and sourceIdentity. Repeated manufacturer codes are deliberately retained as distinct cut-length/usage lines. Measure/cut length belongs in specification: a count of sheets must not silently become linear metres. Administrative DEL, DELZ, ZZZZZZ and End of rows are rejected. Existing inventory is retained, and a BOM source version cannot import twice. A superseded source cannot import. Professional reconciliation against supplier/engineering schedules remains required.

Demo project IDs: SH-TMP-DEMO-LOCKUP and SH-TMP-DEMO-FITOUT. Tender IDs: TMP-DEMO-LOCKUP and TMP-DEMO-FITOUT. Creating both is idempotent and adds projects to context projects plus confirmedProjects for reload persistence. Package records include the requested core schema plus siteRequirements, consentReferences, inspectionRequirements, milestones and tradePricingScopes[{trade,scope,inclusions,exclusions}]. Scope data is illustrative and isDemo:true. Status Open demo does not publish a real tender. Region/model are selectable; pricing remains builder-led and source documents must be attached for real tendering.

Local business schema: tradeBusinesses[{id,name,nzbn,verificationStatus,verificationSource,checkedAt,regions[],regionEvidence,trades[],capabilities,email,phone,updatedAt}]. NZBN validates 13-digit format only. Candidate matching requires manually checked identity evidence/date, business-confirmed service regions and matching trade. Office addresses are not used as service coverage. Shortlists are stored in tenderShortlists scoped to project/trade/business and perform no outreach.

Official [NZBN API](https://www.nzbn.govt.nz/using-the-nzbn/nzbn-services/api/) supports business data lookup after subscription. No live API connection or scraped directory is implemented. Manual identity review links to the [official NZBN register](https://app.nzbn.govt.nz/). Trade licences, competence and insurance require separate checks.

Validation completed: node syntax check; all three empty page renders; idempotent demo seed counts and populated tender scopes; repeated item-code identities with piece quantities preserved; administrative rows, invalid quantities and invalid units rejected; quoted/multiline CSV handling; cross-project BOM isolation; unchecked identity and wrong service-region candidates excluded, checked matching candidates eligible. Root should perform integrated browser QA for actual file persistence and downloads.

Supply-only scopes supplement installer trades: concrete, roofing, fixings, windows/doors for lockup; insulation, joinery, flooring, electrical fittings, plumbing fixtures and additional fixings for fitout. Each requires itemized product/specification, quantity/unit-rate basis and supply exclusions. They cover explicitly unprovided extras or approved alternatives only; all materials already included in SH kitset supply or installer prices are excluded to prevent duplicate pricing. No real supplier partner or product price is fabricated. seedTestProjects migrates missing supply categories/scopes on untouched isDemo records only (no updatedAt), using tradeScopeSchema:2; user-edited packages retain their scopes and need explicit SH review before adding supplier packages. Supply scope coverage and untouched-only migration checks passed.
