# Customer project plan set

New isolated module: `window.SHCustomerPlanSet` exposes `pages: ['Plan set']`, `render(page,c)`, `bind(page,c)`, `panel(c)` and `bindPanel(c)`. Root should load JS/CSS, route Plan set for staff/customer, prepend panel to customer Overview and call bindPanel after DOM insertion. Existing data and inventory/delivery workflows are untouched. Uses the established project-scoped `c.files` API.

No project-specific house imagery or drawings were supplied. The initial state therefore provides a branded, typographic vision panel with explicit missing actual image text. It never presents a fabricated house as contracted. Hero appears only for a selected uploaded JPEG/PNG/WebP belonging to this project. Meaningful alt text and version/purpose/source metadata accompany images. Floor plans and elevations each have separate quick access; full set retains versions and source references. Suggested standard: three renders, front exterior, rear exterior and interior; SH can change the count (1–20) and select any number of relevant renders.

Shared keys: `planSetDocuments[]` with id, projectId, category (Floor plan/Elevations/Render), renderView, name, version, status (Concept/Contract reference/Issued for review/Superseded), provenance, caption, alt, createdAt, and either attachment metadata or sourceDocumentId. `planSetSettings[]` contains projectId, heroDocumentId, selectedRenderIds, standardRenderCount. Metadata saves to the shared browser store; blobs remain in IndexedDB under ownerId=document.id. No base64 data or private BOM source data is included.

Only the staff preview gets upload/link/edit/selection controls. Files are PDF/JPEG/PNG/WebP, nonempty and at most 10 MB, matching the existing evidence store. Registering a Contract reference is an explicit SH purpose choice; upload does not imply consent approval. Every new version can be saved separately and previous versions marked Superseded. Existing customer-visible project documents may be linked through HTTPS; links open in the source service, while external images are never fetched. Linked documents that become private or belong to another project disappear from the customer set. Local files get open/download links only after project and owner checks. Object URLs are revoked on rebind.

The current preview remains device-local with simulated role restrictions. Production needs server permissions, durable project file storage and independent document/contract verification. Publication and root routing are the coordinating agent’s responsibility.

The user-supplied IMG_3289.PNG is bundled as assets/customer-test-house.png as the temporary customer test image. A visible label distinguishes it from the contracted design. Selecting an actual project render takes precedence over this fallback. The test image is not counted as an approved or selected project render.

Cross-device test plans: user-authorized PLANS.pdf is now tracked at dist/downloads/customer-test-plans.pdf and hosted with the private preview. The lockup demo project exposes fixed open/download links even with empty browser storage. The earlier local test entry is hidden when it matches the known duplicate; original local records are retained. Other uploads remain device-local. Bundled plans are demonstration material, not approved scope for the demo project.
